# Rezygisk / ReZygisk Compatibility

## TL;DR

**This module works with Rezygisk (and the Rezygisk CSO loader) out of the box,
no source changes needed.** It also works with stock Magisk Zygisk and the
KernelSU / APatch Zygisk-Next implementations.

## Why it works

The native loader uses only the Zygisk public ABI and stays well within the
subset of the API that every reimplementation supports:

| Concern                        | This module                                                          | Rezygisk support |
|--------------------------------|----------------------------------------------------------------------|------------------|
| `ZYGISK_API_VERSION`           | `2` (declared in `module/src/jni/zygisk.h`)                          | v1 - v4 supported |
| Companion process              | **Not used.** No `Api::connectCompanion()` / `REGISTER_ZYGISK_COMPANION` | n/a (not invoked) |
| `Api::setOption(...)`          | Only `DLCLOSE_MODULE_LIBRARY`                                        | supported in v1+ |
| `Api::hookJniNativeMethods`    | Not used                                                             | n/a |
| `AppSpecializeArgs.nice_name`  | Read in `postAppSpecialize`                                          | supported |
| Platform calls                 | `dlopen` / `xdl_open` / Dobby inline hooks done **in the app process** after `postAppSpecialize` | not zygote-side, no IPC |

Because the loader does all of its work *inside the target app process* after
`postAppSpecialize`, it has no dependency on Magisk-specific zygote daemon
behaviour. The only requirement on the Zygisk implementation is that
`postAppSpecialize` is invoked with a usable `nice_name` - which Rezygisk,
Zygisk-Next and stock Magisk all do.

## Rezygisk CSO loader

Rezygisk's "Custom Shared-Object loader" (sometimes called the CSO loader)
discovers modules by scanning each module directory for a `zygisk/<abi>.so`
shared object that exports the standard Zygisk module entry point. The build
output of this module follows that convention exactly:

```
voidwalker-vX.Y.Z-release.zip
└── zygisk/
    ├── arm64-v8a.so
    ├── armeabi-v7a.so
    ├── x86.so
    └── x86_64.so   (when bundled)
```

The flat per-ABI naming is generated by the `prepareMagiskFiles<Variant>`
Gradle task; see `module/build.gradle`.

## Tested combinations

Smoke-tested loader paths:

- Magisk 26.x with built-in Zygisk
- Rezygisk (latest release at the time of this commit) on KernelSU
- Zygisk-Next via APatch

If you hit an issue under any Zygisk implementation, attach
`adb logcat -s VoidWalker` output to the bug report.
